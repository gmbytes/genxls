# xlsgen

将策划表（Excel **`.xlsx` / `.xls`** 或 **TSV**）解析后，导出：

- 聚合数据 JSON（默认 **`all.json`**，可用 **`--all-json`** 指定路径与文件名）（可选）
- 按表拆分的 **`tables/*.json`** 与 **`manifest.json`**（可选）
- **Go** 源码（默认 **`xls.gen.go`**，`package xls`；可用 **`--go-out`** / **`--pkg`** 自定义）
- **GDScript**：配置表行 **`c_<编号>_<sheet snake>.gd`**、表容器 **`c_<编号>_<类型复数 snake>.gd`**、自定义结构体 **`d_*.gd`**、根汇总 **`all_config.gd`**

本目录为独立 Go 模块 **`xlsgen`**（见 `go.mod`），仓库路径 `tools/xlsgen`。生成文件头注释为 **Auto-generated by xlsgen**。

## 运行

在 `tools/xlsgen` 下：

```bash
go run . --in ./test --out ./gen --lang all
```

指定生成的 Go 文件名与包名（例如 `config.gen.go`、`package config`）：

```bash
go run . --in ./test --out ./gen --lang go --go-out ./gen/config.gen.go --pkg config
```

将聚合 JSON 写到其它路径或改名（例如 `./dist/config_data.json`）：

```bash
go run . --in ./test --out ./gen --all-json ./dist/config_data.json
```

或编译后执行：

```bash
go build -o xlsgen .
./xlsgen --in ./test --out ./gen
```

- **`--in` 省略**时默认为 **`xls`**（当前目录下的 `xls` 目录）。
- 若 `--in` 路径不存在，会再尝试 **`./xls/<basename>`**（与当前工作目录组合）。

## 命令行参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--in` | `xls` | 输入：**目录**（扫描其中 `.xlsx`/`.xls`，按文件名排序）、**单个 Excel 文件**，或 **TSV 文件**（制表符分隔）。目录内**不会**自动拾取 `.tsv`，需把 TSV 路径直接传给 `--in`。 |
| `--out` | `.` | 输出根目录；默认 Go 文件（见 `--go-out`）、默认聚合 JSON（见 `--all-json`）与 **`--split-json`** 的父目录。 |
| `--gd-out` | `<out>/gd` | `--lang` 含 `gd` 时 GDScript 输出目录。 |
| `--lang` | `all` | `go`、`gd`、`all`（= go+gd），或逗号分隔如 `go,gd`。其它值报错。 |
| `--pkg` | `xls` | 生成 Go 文件的 **`package`** 名。 |
| `--go-out` | （空） | 生成 Go 源码的**输出文件路径**（含目录与文件名）。省略时为 **`<out>/xls.gen.go`**。父目录不存在时会自动创建。 |
| `--flag` | 空 | `server` \| `client`，与字段上的 `,s` / `,c` 联用（见下文）。非法值报错。 |
| `--json` | `true` | 是否写出聚合 JSON。 |
| `--all-json` | （空） | 聚合 JSON 的**输出文件路径**（含目录与文件名）。省略时为 **`<out>/all.json`**。父目录不存在时会自动创建。 |
| `--split-json` | `false` | 是否在 `--out` 下写出 **`tables/<jsonKey>.json`** 与 **`manifest.json`**。 |
| `-v` | `false` | 详细日志（打印生成路径）。 |

## 处理流程概览

1. **`--in`** 解析为若干输入文件路径（见上）。
2. **第一轮**仅对能被 `excelize` 打开的 **`.xlsx`/`.xls`** 扫描**所有工作表**：首格为 **`struct_def`**（不区分大小写）的表视为**结构体定义表**，解析出自定义类型（供后续表头引用）。**TSV 不参与结构体定义扫描**。
3. **第二轮**逐文件处理：能打开为 Excel 的则按**工作表**处理；否则按 **TSV** 整文件当作一张表，表名 = **文件名去扩展名**。
4. 全量输入合并为同一 **`AllConfig`** / 聚合 JSON。不同来源若得到相同 **JSON 键**会报错退出。
5. 数据表工作表名经 **`ExportName`** 得到 **类型名**（PascalCase），再 **`PluralizeTypeName` + `LowerFirst`** 得到 JSON 字段键（如 `Item` → `items`）。

## 结构体定义表（自定义类型）

**判定**：该表首行首列单元格为 **`struct_def`**。

**格式**（可重复多块，块与块之间可有空行）：

1. 一行：首列 `struct_def`（其余列可为策划注释，工具不解析为字段）。
2. 下一行：首列为**结构体名**（如 `Vector`）；从**第 2 列起**为字段定义，语法与数据表相同：`name#type`（结构体表上**不支持** `,s`/`,c` 标记；字段也不按 `--flag` 过滤）。

解析顺序即定义顺序；后文数据表类型可引用先前已定义的结构体名。**禁止自引用**（定义 `Foo` 时字段类型不能为 `Foo` / `Foo[]` 等）。

**与数据表的命名冲突**：若某数据表工作表名导出后的 **类型名** 与已注册的自定义结构体同名，报错。

> 文件名任意，常见如 `0.struct.xlsx`；关键是工作表内容符合上述规则。

## 数据表与跳过规则

- **全空表**（所有单元格为空）：**跳过**，不导出（便于忽略 Excel 默认空 Sheet）。
- **结构体定义表**：不作为配置数据导出。
- 其余表需能通过表头检测，且含必填 **`cid#int`**。

## 表头行数与朝向

通过「定义行」是否出现 `name#type` 形态自动判断 **1 / 2 / 3 行表头**：

| 行数 | 含义 |
|------|------|
| 1 | 第 1 行即字段定义行。 |
| 2 | 第 1 行注释（忽略）；第 2 行字段定义。 |
| 3 | 第 1 行 A1：空或 `1` 为横向；**`2` 为纵向（当前不支持，报错）**；第 2 行注释；第 3 行字段定义。 |

## 字段定义

单元格须匹配：

```text
name # type [,s|c]
```

（`#` 两侧允许空格；`name` 为标识符。）

- **`#comment` / `#common`** 或类型为 **`comment` / `common`**：列不导出。
- **`,s`**：仅 **`--flag server`** 时保留该列。
- **`,c`**：仅 **`--flag client`** 时保留该列。
- **未传 `--flag`**：`s`/`c` 列仍参与 schema 与 JSON（与传 flag 时的过滤行为不同）。

**必填**：每张数据表在导出字段中须包含 **`cid#int`**。

## 类型与 Go / GDScript 映射

**基础标量**（`int`/`int32` → Go `int`；`int64` → `int64`；`float*` → `float64`；`bool`；`string`）：

| 表头类型 | Go | GDScript `@export` |
|----------|-----|---------------------|
| `int` / `int32` / `int64` | `int` / `int` / `int64` | `int` |
| `float` / `float32` / `float64` | `float64` | `float` |
| `bool` | `bool` | `bool` |
| `string` | `string` | `String` |

**数组 / 矩阵**（`[]` 后缀层数 1 或 2）：

- **数值类** `int`/`int32`/`int64`、`float*`：Go 为 `[]T` / `[][]T`；一维、二维在 GD 中多为 `Array[int]`、`Array[float]` 或二维 `Array`（无元素类型注解）。
- **`bool` / `string` 的数组**：表头可被映射为 Go 切片且 GD 有 `Array[bool]` / `Array[String]` 声明，但从 **Excel 字符串单元格**解析时，当前实现**仅支持标量** `bool`/`string`；若声明为 `bool[]`/`string[]` 等并填单元格，会在解析阶段失败。请仅用数值类做矩阵/向量式填表，或对复杂结构使用 **JSON 字符串 + 自定义结构体** 等组合策略。

**自定义结构体**（来自结构体定义表，类型名为 PascalCase，如 `Vector`）：

| 表头 | Go | GDScript |
|------|-----|----------|
| `Vector` | `Vector` | `CVector`（`class_name`，文件 `d_vector.gd`） |
| `Vector[]` | `[]Vector` | `Array[CVector]` |
| `Vector[][]` | `[][]Vector` | `Array`（二维无元素类型） |

**配置表行类型**与**结构体定义表生成的行类型**在 GD 中均为 **`C` + 类型名**（如 `CTest`、`CVector`）；配置表行脚本文件名为 **`c_<编号>_<sheet snake>.gd`**（`<编号>` 见下表），结构体表仍为 **`d_<snake>.gd`**（仅文件名区分来源）；表级容器为 **`C` + 复数类型名**，文件 **`c_<编号>_<类型复数 snake>.gd`**，内含 `@export var items: Array = []`。结构体类型名与数据表 sheet 导出名不得重名（生成器会报错），故不会出现两个不同脚本共用同一 `class_name`。

## 单元格取值

- **空单元格**：类型零值（含空数组、空对象）。
- **复合空标记**：对数组、矩阵及自定义类型，单元格为 **`{}`** 或 **`[]`** 时与空单元格等价（视为空数组/空结构等）。
- **数值一维 / 二维**：字符串可为 **JSON 数组**，或 **花括号**写法（内部将 `{`/`}` 换为 `[`/`]` 后按 JSON 解析），如 `"{1,2,3}"`、`"{{1,2},{3,4}}"`。
- **`bool` 标量**：`true`/`false`、`1`/`0`。
- **自定义结构体单格**：可为 **JSON 对象**（键为字段 `rawName`），或 **按字段顺序**的花括号元组，如 `"{1,2,3}"` 对齐结构体字段顺序。

## 输出说明

### Go 源码（`--lang` 含 `go`）

输出路径由 **`--go-out`** 决定；默认 **`<out>/xls.gen.go`**，包名为 **`--pkg`**（默认 **`xls`**）。

- 先按结构体定义表出现顺序输出 **`type Vector struct { ... }`** 等。
- 再输出 **`type AllConfig struct`**，字段为各表 **`PluralizeTypeName(typeName)`**，类型 **`[]TypeName`**，`json` tag 为对应 **JSON 键**（小写首字母的复数字段名）。
- 各表行类型：`json` tag 为列 **raw 名**（如 `cid`）。

### GDScript（`--lang` 含 `gd`）

写入 `--gd-out`（默认 `<out>/gd`）：

| 文件模式 | 说明 |
|----------|------|
| `d_<snake>.gd` | 结构体定义表：`class_name C<Type>`（与配置表行类名规则一致） |
| `c_<编号>_<sheet snake>.gd` | 配置表行：`class_name C<Type>`，`cid` 字段在脚本中排在前列。`<编号>`：工作簿 stem（无扩展名）按 `.` 分段，**自左起第一个非空段**若全为十进制数字则按数值至少两位补零（如 `1`、`01` → `01`，`100` → `100`）；否则取 **整个 stem 最前面的连续数字**；仍无则 `00`。`<sheet snake>` 为 **sheet 标签**经非法文件名字符替换与 `snake_case`。例：`1.character.xlsx` 中 sheet `Charachter` → `c_01_charachter.gd`；`00.struct.xlsx` → 前缀 `00`。 |
| `c_<编号>_<snake_plural>.gd` | 表容器：`class_name C<Plural>`，`@export var items: Array = []`，`<编号>` 同行脚本；`<snake_plural>` 为 **`PluralizeTypeName(ExportName(sheet))`** 的 snake_case（保证如 `Box`→`Boxes` 等复数规则正确）。 |
| `all_config.gd` | `class_name CAllConfig`，各表 `@export var <snake_plural>: Array = []` |

工具**不**调用 Godot、**不**生成 `.res`；需要二进制 Resource 时在引擎侧自行导入或封装。

### 聚合 JSON（默认 `all.json`）

由 **`--all-json`** 决定磁盘路径；内容与历史上 **`all.json`** 相同：顶层键为各表 JSON 键；值为行对象数组；行内键为字段 **raw 名**。

### `--split-json`

在 `--out` 下生成：

- `tables/<jsonKey>.json`：该表行数组（**仅数组**，非带键对象）。
- `manifest.json`：`version` 为生成日 **`YYYYMMDD`**；`tables` 内每项含 `file`、`sha256`、`size`、`row_count`、`type_name`（PascalCase 类型名）。

## 代码布局（供二次开发）

| 包路径 | 职责 |
|--------|------|
